1. Distributed Denial of Service (DDoS)

Definition: An attack that overwhelms a website or online service with excessive traffic from multiple sources, rendering it inaccessible to legitimate users.

Mechanism: Attackers use a botnet (a network of infected devices) to generate a massive volume of requests, saturating the target's resources.

Example: An e-commerce site is overwhelmed with traffic from thousands of infected computers, causing it to crash during a major sales event. Countermeasure: Traffic filtering, rate limiting, and DDoS mitigation services (like Cloudflare).

2. Insecure Network Protocols

Definition: Protocols that lack security measures or authentication, making them vulnerable to interception and exploitation.

Mechanism: Data is transmitted in plaintext, allowing eavesdropping. Examples include HTTP, FTP, and Telnet.

Example: Using Telnet or FTP for remote server access allows potential eavesdropping on credentials and data. Countermeasure: Use modern encrypted alternatives like HTTPS, SFTP, and SSH.

3. Malware (Ransomware)

Definition: Malicious software designed to damage, disrupt, or gain unauthorized access to systems.

Mechanism: Includes viruses, worms, trojans, spyware, and keyloggers. Ransomware specifically encrypts files and demands payment for the decryption key.

Example: A ransomware attack encrypts a company's files, halting operations until a ransom is paid. Countermeasure: Regular offline backups, antivirus software, and user education against clicking suspicious links.

4. Man-in-the-Middle (MitM)

Definition: The attacker secretly intercepts and possibly alters the communication between two parties who believe they are directly communicating with each other.

Mechanism: Eavesdropping and data manipulation. Often uses ARP spoofing to redirect traffic through the attacker.

Example: An attacker intercepts a Wi-Fi connection at a café to capture credit card information sent during an online purchase. Countermeasure: End-to-end encryption (HTTPS, VPNs) and avoiding unsecured public Wi-Fi.

5. Phishing Attacks

Definition: Fraudulent attempts to obtain sensitive information such as usernames, passwords, and credit card details by disguising oneself as a trustworthy entity in electronic communications.

Mechanism: Social engineering and spoofed emails/websites. Targets the user, not the software. Spear phishing targets a specific person.

Example: An email that appears to be from a bank asking recipients to confirm their account details on a fake website. Countermeasure: User education, email filtering, and multi-factor authentication (MFA).

6. SQL Injection (SQLi)

Definition: An attack that involves inserting malicious SQL statements into an input field for execution to manipulate or exploit SQL databases.

Mechanism: Exploits insufficient validation of user input. The injected code executes on the server, allowing data extraction, modification, or deletion.

Example: Entering Robert'); DROP TABLE Students; -- in a form could delete the whole database. Countermeasure: Input validation, parameterized queries (prepared statements), and stored procedures.

7. Cross-Site Scripting (XSS)

Definition: A vulnerability in web applications that allows attackers to inject malicious scripts into content viewed by other users.

Mechanism: The attacker embeds a script (often JavaScript) into user-generated content. When other users view the page, the script executes in their browser.

Example: A comment on a blog that contains a script which, when viewed, steals cookies from other users (Session Hijacking). Countermeasure: Input sanitization, output encoding, and Content Security Policy (CSP).

8. Unpatched Software

Definition: Software that has not been updated with the latest security patches, making it vulnerable to exploitation.

Mechanism: Attackers scan for known vulnerabilities (CVEs) that have available patches but have not been applied. Publishing a patch makes an unpatched system an easier target.

Example: An operating system that has not been updated, allowing attackers to exploit a known vulnerability. Countermeasure: Automated patch management and vulnerability scanning.

9. Weak Authentication

Definition: Security measures that are easy to bypass or crack, often due to simple or predictable passwords, or lack of multifactor authentication.

Mechanism: Short passwords can be brute-forced in seconds. Credential stuffing uses passwords leaked from other breaches (because people reuse passwords).

Example: A website that only requires a username and a simple password, without requiring any additional form of verification (MFA). Countermeasure: Strong password policies, Multi-Factor Authentication (MFA), and account lockout mechanisms.

10. Zero-Day Exploits

Definition: Attacks that take advantage of a previously unknown vulnerability in software or hardware before the developer has released a patch or the public is aware of it.

Mechanism: Because the vulnerability is unknown, there are no defenses (no antivirus signature, no firewall rule). Highly sought after by criminals and nation-states.

Example: Stuxnet was a zero-day used to break Iran's uranium-enrichment centrifuges in 2006, suspected to be created by the US NSA. Countermeasure: Advanced behavioral analysis tools (EDR), zero-trust architecture, and rapid incident response.

11. How Vulnerabilities Combine

A real breach rarely uses one vulnerability. An exam scenario usually describes a chain of them.

The Chain: 1. Phishing email steals credentials → 2. Weak authentication (no MFA) allows login → 3. Attacker exploits unpatched software for root control → 4. Malware encrypts files.

Breaking the chain: Identifying just one link in the chain (e.g., enforcing MFA) can break the entire attack.
